# 08 · 硬件：接线、IP、安装

> 这份文档解决"雷达怎么接、IP 怎么配、装在狗身上哪个位置"。

---

## 1. 接口与供电

### 拓展坞这边

Go2 拓展坞的可用接口（以实机为准）：

| 接口 | 能力 | 用途 |
|---|---|---|
| RJ45 #1（内部） | 千兆 | 宇树内网，`192.168.123.18`，**不要动** |
| RJ45 #2 | 千兆 | 有线调试（接 PC）—— 本方案改用 Wi-Fi 后空出 |
| **M8 航插** | **百兆以太网 + 12 V/2 A** | **雷达专用，本方案推荐** |
| XT30 | 12 V/3 A、5 V/3 A | 外设供电 |

### Mid360 这边

| 项目 | 值 |
|---|---|
| 功耗 | 稳态约 6.5 W，启动峰值 18 W（约 8 秒），低温自加热约 14 W |
| 网口 | 100BASE-TX（百兆够用：200 k 点/s ≈ 3.6 MB/s ≈ 29 Mbit/s） |
| 供电 | 9–27 V |
| 连接器 | 零售版是 M12 一分三线（RJ45 + 电源裸线）；宇树套装是 M8→M12 复合线 |

**供电余量核算**：M8 口给 12 V/2 A = 24 W，雷达峰值 18 W → 余量 33%，够用。
但要注意**峰值出现在上电 8 秒内**，如果同时挂了别的外设，可能瞬时欠压导致雷达反复重启。

### 三种接法

**A. 宇树套装（推荐）**
M8 复合线一插到底：网口 + 供电都在这根线上，不需要额外走线。

**B. 零售版 + 交换机**
零售 Mid360 只有 M12 一分三线（RJ45 + 电源裸线）。此时：

```
拓展坞 RJ45 #2 ──┐
                 ├── 千兆交换机 ── Mid360 的 RJ45
XT30 12V/3A ─────┘（电源接 Mid360 的裸线，注意正负极）
```

雷达要和拓展坞在**同一网段**（下面 §2）。

**C. 雷达直连拓展坞 RJ45 #2**
把网线从 PC 上拔下来插雷达，电源走 XT30。缺点是雷达和 PC 抢同一个口 ——
这也正是本方案要上 Wi-Fi 的原因。

## 2. IP 配置

### 目标

```
拓展坞（eth1 / M8）  192.168.123.18     ← 与本机 eth0 同网段，便于路由
Mid360              192.168.123.20
PC（Wi-Fi）          由路由器分配
```

> **为什么统一用 `192.168.123.x`：** 宇树内网已经是这个网段，雷达放在这里不需要额外路由；
> 而且避开了 Mid360 出厂默认的 `192.168.1.1xx`（很多家用路由器也用 `192.168.1.0/24`，
> 会撞车导致路由走错网卡）。

### 改雷达 IP（出厂默认不是 123.20 时）

1. PC 有线接雷达（或接交换机），把 PC 网卡设成雷达同网段，例如 `192.168.1.50/24`
2. 打开 **Livox Viewer 2** → 选中设备 → 设置：

   | 项目 | 值 |
   |---|---|
   | IP | `192.168.123.20` |
   | 子网掩码 | `255.255.255.0` |
   | 网关 | `192.168.123.1` |
   | LidarInfo IP | `192.168.123.70` |

3. 把雷达接回拓展坞，验证：

   ```bash
   ping -c2 192.168.123.20
   ```

### 改驱动配置

`src/livox_ros_driver2/config/MID360_config.json`：

```json
{
  "host_net_info": {
    "cmd_data_ip": "192.168.123.18",
    "push_msg_ip": "192.168.123.18",
    "point_data_ip": "192.168.123.18",
    "imu_data_ip": "192.168.123.18"
  },
  "lidar_configs": [
    { "ip": "192.168.123.20", "pcl_data_type": 1, "pattern_mode": 0, "extrinsic_parameter": {...} }
  ]
}
```

> 用 `--symlink-install` 编译时，改 `src` 里的文件**立即生效**，不需要重新编译。

**本仓库里这个文件已经按上面的值改好了**（上游 Livox 默认是 `192.168.120.x` 网段）。
也就是说，只要你的雷达按出厂 IP `192.168.123.20` 用、拓展坞是 `192.168.123.18`，
这一步可以跳过；换过 IP 的机器才需要改这里。核对一条命令：

```bash
grep -E 'point_data_ip|"ip"' src/livox_ros_driver2/config/MID360_config.json
```

## 3. 安装位置

### 硬约束

| 约束 | 数值 | 说明 |
|---|---|---|
| 底面安装孔 | 4 × M3，**孔深仅 5 mm** | 必须用 **M3×8** 螺钉，长了会顶到底板 |
| 垂直 FOV | −7° ~ +52° | 不是对称的，装低了看不到近处地面 |
| 建议高度 | 头顶上方 **15–20 cm** | 避开狗自身遮挡，同时保证近处视野 |
| 重量 | 265 g | 加支架与线束，建议按 400 g 设计固定 |

### 支架

两种做法：

- **宇树官方支架**：孔位匹配，最省事
- **自制 3–4 mm 铝板**：按 4×M3 孔位开孔，中间留走线孔，下方垫 1 mm 硅胶垫减振

减振很重要 —— 四足行走的高频振动会直接进 IMU，表现为静止时位姿抖动。
硅胶垫 + 扎带固定线束（线束摆动同样会引入噪声）。

### 与内置 L1 雷达共存 ⚠️

Go2 自带一个 L1 固态雷达（用于避障）。**两个激光雷达的出光面互相对射有损伤风险**，
Livox 手册对此有明确警告。

处置（任选其一）：

1. **错高 ≥ 10 cm**：把 Mid360 装得明显高于 L1 的扫描平面
2. **遮住 L1 的出光窗口**：如果不用内置避障，用不透明胶带/贴片挡住 L1 窗口
3. **改变朝向**：让两者的出光面不共面（但仍需满足高度差）

> 只做软件层面的"关掉 L1 话题"是**不够**的 —— 雷达仍在出光，物理损伤风险依旧。

## 4. 上电顺序与验证

```
1. 电池上电 → 狗站立/趴下
2. 拓展坞开机（约 30 秒）
3. 雷达上电（12 V）
4. 等雷达自检完成（约 8 秒，此时功耗峰值最高）
5. ssh 进拓展坞 → 校时 → 放开功耗模式 → 起建图
```

验证清单：

```bash
# ① 雷达链路
ping -c 5 192.168.123.20                     # 0% 丢包

# ② 雷达在出数据（UDP 56300 是 Mid360 的数据口）
sudo tcpdump -i eth1 -c 20 udp port 56300     # 网卡名按实际改

# ③ 驱动起来了
ros2 topic hz /livox/lidar                    # 约 10 Hz
ros2 topic hz /livox/imu                      # 约 200 Hz

# ④ 建图正常
ros2 topic hz /cloud_registered               # 约 10 Hz
ros2 topic hz /flmap/cloud                    # 约 5 Hz

# ⑤ 温度
for z in /sys/class/thermal/thermal_zone*/temp; do awk '{printf "%.0f ", $1/1000}' $z; done
```

## 5. 常见硬件问题

| 现象 | 原因 | 处置 |
|---|---|---|
| `ping` 雷达不通 | 网段不同 / 网线只通电不通数据 / 雷达没上电 | 先看雷达指示灯；换线；PC 直连改 IP |
| 雷达反复重启 | 供电瞬时欠压 | 单独供电，别和别的外设共用一个 12 V |
| `tcpdump` 有包但驱动无数据 | `host_net_info` 里的 IP 与本机不一致 | 改 `MID360_config.json` |
| 点云整体倾斜 | 外参 `extrinsic_R` 与实际安装不符 | 重新标定，或先用单位阵确认能跑 |
| 静止时点云抖 | 支架刚性不足 / 线束摆动 | 加硅胶垫、扎紧线束 |
| 行走时点云拖影 | CPU 降频（过热） | `nvpmodel -m 0` + `jetson_clocks` + 检查风扇 |
